Track 1 · Autonomous Agents

  1. Run it yourself. In the dashboard, "Run the council live" gathers fresh RYO evidence and convenes the council on any symbol (one to two minutes, capped per visitor).
  2. Real thinking (25). Open any receipt: each agent cites dotted paths into RYO's answer, and the value shown is read back out of the evidence, not retyped by the model. Citations to paths that do not exist are dropped in code.
  3. Cause and effect (20). "What changed" ranks every evidence move since the previous receipt by impact; the derivatives gate withholds RYO fields that are not about the token (see a receipt's Warnings).
  4. Repeatability (10). Press Verify replay: the decision is rebuilt from the stored evidence and prints identical: true. Offline: uv run nota replay <id>. Each receipt is also anchored in Bitcoin (OpenTimestamps).
  5. Advanced (5). Practice trades sized from ATR with stops and targets, a twice-daily ledger cycle in CI, and every agent scored by Brier against the token's own base rate.
  6. The spotlight idea, built. The multi-KOL agent reads up to 20 voices (X, Telegram, Bluesky), finds the tokens they name with sentiment, conviction and urgency, and opens a practice position only when the voices converge and every user rule passes. Each rule is shown with the value it read and its threshold; the stop comes from RYO's ATR, and with no RYO evidence there is no trade. Stored runs replay offline: uv run nota kol-replay <id>. X voices fall back to Tavily search when X refuses, marked "coverage partial".

Track 2 · Dashboards & Interfaces

  1. Easy to read (25). Open the dashboard: each receipt starts with a five-line summary (now, biggest change, position, what RYO said, next step).
  2. Sorted by importance (25). "Needs attention" sits on top; "What changed" is sorted by impact; the scorecard puts the next settlements first.
  3. Works for everyone (10). Keyboard only: j/k, Enter, p, /, ?. Skip links, checked contrast, reduced motion, light and dark, and a Japanese overview.

Track 3 · New Skills

  1. Fills a gap (25). positioning_check: RYO reports open interest and funding, but some of those fields carry the same value across unrelated tokens. The skill checks RYO's derivatives against OKX for the token and withholds what is not token-specific.
  2. Follows the spec (15). Every skill returns RYO's envelope (status, data_mode, availability, warnings) at RYO's own path shape: GET /api/skills/, POST /api/skills/{name}/invoke. Try one in the dashboard's "Run a skill".
  3. Could we use it (20). contrib/positioning_check/ in the repository is a drop-in: no Nota imports, a FastAPI router RYO can include, and its own tests. The same skills are an MCP server at /mcp.

What only Nota does

  • It audits RYO itself. The Verdict Scorecard locks RYO's own verdict and trade plan for 25 majors every day and settles each one on OKX candles at 24 and 72 hours, every miss counted.
  • It found a defect in RYO's data: one open-interest figure repeated across unrelated tokens, now withheld by a gate.
  • Every lock and receipt is anchored in Bitcoin and every pushed ledger snapshot is attested with Sigstore.
